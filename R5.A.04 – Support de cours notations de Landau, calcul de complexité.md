## 1. Pourquoi mesurer un algorithme ?

Un programme « qui marche » peut être inutilisable dès que les données grossissent. On cherche donc à exprimer le **coût** d'un algorithme (temps, mémoire) **en fonction de la taille n de l'entrée**, indépendamment de la machine et du langage.

**Modèle de coût.** On compte des opérations élémentaires (comparaison, affectation, accès à une case, opération arithmétique), chacune pour un coût constant. C'est une simplification : en Python, `x in liste` n'est pas « une opération », c'est une boucle cachée de longueur n. Savoir ce que cache chaque instruction fait partie du métier.

**Trois cas à distinguer.**

- **Meilleur cas** : l'entrée la plus favorable (liste déjà triée pour le tri par insertion).
- **Pire cas** : l'entrée la plus défavorable (liste triée en sens inverse). C'est celui qu'on garantit.
- **Cas moyen** : moyenne sur une distribution d'entrées (hypothèse à préciser : par exemple « toutes les permutations équiprobables »).

**Taille de l'entrée.** À préciser à chaque fois : nombre d'éléments d'une liste, nombre de caractères d'un texte, nombre de tokens, ou encore nombre de bits d'un entier.

## 2. Les notations de Landau

On compare la **vitesse de croissance** de fonctions positives f(n) et g(n), pour n grand.

### 2.1 Définitions

| Notation | Lecture | Définition formelle | Sens intuitif |
| --- | --- | --- | --- |
| f = O(g) | f est dominée par g | il existe c > 0 et n₀ tels que, pour tout n ≥ n₀ : f(n) ≤ c · g(n) | **borne supérieure** : f ne croît pas plus vite que g |
| f = Ω(g) | f domine g | il existe c > 0 et n₀ tels que, pour tout n ≥ n₀ : f(n) ≥ c · g(n) | **borne inférieure** : f croît au moins aussi vite que g |
| f = Θ(g) | f est du même ordre que g | f = O(g) **et** f = Ω(g) | **ordre exact** de croissance |
| f = o(g) | f est négligeable devant g | f(n) / g(n) tend vers 0 | f croît **strictement** moins vite que g |

**Exemple.** Montrons que 3n² + 5n + 2 = Θ(n²).

- Borne sup : pour n ≥ 1, 5n ≤ 5n² et 2 ≤ 2n², donc 3n² + 5n + 2 ≤ 10 n². Avec c = 10 et n₀ = 1, on a bien O(n²).
- Borne inf : 3n² + 5n + 2 ≥ 3n² pour tout n. Avec c = 3, on a Ω(n²).
- Conclusion : Θ(n²).

### 2.2 Propriétés utiles

- **Les constantes multiplicatives disparaissent** : 50 n = Θ(n). Le terme dominant l'emporte : n² + 1000 n = Θ(n²).
- **Somme** : O(f) + O(g) = O(max(f, g)). Deux étapes consécutives : on garde la plus coûteuse.
- **Produit** : O(f) · O(g) = O(f · g). Des boucles imbriquées : on multiplie.
- **Transitivité** : si f = O(g) et g = O(h) alors f = O(h).
- **Changement de base du logarithme** : log₂ n = Θ(log₁₀ n) = Θ(ln n), car deux logarithmes diffèrent d'un facteur constant. On écrit donc simplement log n.
- **Les polynômes** : un polynôme de degré k est Θ(nᵏ).

### 2.3 Hiérarchie des croissances

Pour n grand, on a la chaîne suivante (chaque classe est négligeable devant la suivante) :

**1 < log n < √n < n < n log n < n² < n³ < 2ⁿ < n! < nⁿ**

| Classe | Nom courant | n = 10³ | n = 10⁶ | Exemple |
| --- | --- | --- | --- | --- |
| O(1) | constant | 1 | 1 | accès `t[i]`, accès `dict` (en moyenne) |
| O(log n) | logarithmique | 10 | 20 | recherche dichotomique |
| O(n) | linéaire | 10³ | 10⁶ | parcours, recherche séquentielle |
| O(n log n) | quasi-linéaire | 10⁴ | 2·10⁷ | tri fusion, tri par tas, `sorted` |
| O(n²) | quadratique | 10⁶ | 10¹² | tri par insertion, deux boucles imbriquées |
| O(2ⁿ) | exponentiel | ≈ 10³⁰¹ | inimaginable | Fibonacci récursif naïf, sous-ensembles |

À raison de 10⁹ opérations par seconde (en C, bien plus lent en Python), un algorithme en n² sur 10⁶ éléments demande 10³ s, soit environ un quart d'heure ; en n log n, 0,02 s.

### 2.4 Erreurs classiques à éviter

1. **« O » n'est pas une égalité.** On écrit f = O(g) par abus ; cela signifie « f appartient à l'ensemble O(g) ». On ne peut pas dire O(n) = O(n²) dans le sens inverse de l'inclusion.
2. **O est une borne supérieure, pas une borne exacte.** « Le tri par insertion est en O(n³) » est *vrai* mais peu informatif. Quand on le peut, on donne Θ.
3. **Ne pas confondre le cas et la borne.** « Pire cas » et « O » sont deux choses indépendantes : on peut donner une borne Ω du pire cas, ou une borne O du meilleur cas.
4. **Les constantes comptent en pratique.** Θ(n log n) avec une constante 1000 peut perdre contre Θ(n²) avec une constante 1 pour n petit. La notation de Landau décrit un comportement **asymptotique**.
5. **La taille de l'entrée.** Pour un entier N, la taille est log N bits : tester si N est premier par division jusqu'à √N coûte O(√N) divisions, soit un temps **exponentiel en la taille** de l'entrée.

## 3. Calculs de complexité sur des exemples simples

### 3.1 Méthode

1. Choisir la **taille n** et l'**opération** dominante à compter.
2. Pour une **séquence** d'instructions : additionner les coûts (on garde le maximum).
3. Pour une **boucle** : (nombre d'itérations) × (coût d'une itération). Si le coût d'une itération varie avec l'indice, écrire une **somme**.
4. Pour une **condition** : le maximum des deux branches (pire cas).
5. Pour un **appel de fonction** : le coût de la fonction appelée, avec les arguments effectifs.
6. Simplifier avec les règles de la section 2.2.

### 3.2 Exemples

**Exemple 1 : boucle simple.**

```python
def somme(t):
    total = 0              # 1 opération
    for x in t:            # n itérations
        total += x         # 1 opération
    return total
```

Coût : 1 + n · 1 = n + 1, soit **Θ(n)**.

**Exemple 2 : deux boucles imbriquées indépendantes.**

```python
def paires(t):
    n = len(t)
    compteur = 0
    for i in range(n):
        for j in range(n):
            if t[i] + t[j] == 0:
                compteur += 1
    return compteur
```

Coût : n · n = **Θ(n²)**.

**Exemple 3 : boucle imbriquée « triangulaire ».**

```python
def doublons(t):
    n = len(t)
    for i in range(n):
        for j in range(i + 1, n):      # n - 1 - i itérations
            if t[i] == t[j]:
                return True
    return False
```

Le nombre de comparaisons dans le pire cas (aucun doublon) est la somme (n−1) + (n−2) + … + 1 = n(n−1)/2 = n²/2 − n/2. C'est **Θ(n²)**, avec une constante deux fois plus petite que l'exemple 2 : la forme de la boucle ne change pas la classe.

*Rappel de la somme d'une suite arithmétique :* 1 + 2 + … + k = k(k+1)/2.

**Exemple 4 : boucle logarithmique.**

```python
def puissances(n):
    i = 1
    while i < n:
        i *= 2
    return i
```

Après k tours, i = 2ᵏ. La boucle s'arrête quand 2ᵏ ≥ n, c'est-à-dire k ≈ log₂ n. Coût : **Θ(log n)**. Même résultat si on divise par 2 à chaque tour.

**Exemple 5 : un piège, la boucle dont le travail décroît.**

```python
def decroissant(n):
    i = n
    while i > 0:
        for j in range(i):
            pass                  # travail unitaire
        i //= 2
```

Le travail total est n + n/2 + n/4 + … ≤ 2n. C'est **Θ(n)**, pas Θ(n log n) : le nombre de tours est log n, mais la plupart sont très peu coûteux. Série géométrique : 1 + 1/2 + 1/4 + … = 2.

**Exemple 6 : boucle externe linéaire, boucle interne logarithmique.**

```python
def mixte(n):
    for i in range(n):
        j = 1
        while j < n:
            j *= 2
```

Coût : n · log n = **Θ(n log n)**.

**Exemple 7 : meilleur et pire cas.**

```python
def recherche(t, x):
    for i in range(len(t)):
        if t[i] == x:
            return i
    return -1
```

Meilleur cas : x en première position, **Θ(1)**. Pire cas : x absent, **Θ(n)**. Cas moyen (x présent, position uniforme) : (n+1)/2 comparaisons, **Θ(n)**. Cette fonction est donc en **O(n)** et en **Ω(1)** : elle n'a pas de Θ global, il faut préciser le cas.

### 3.3 Le coût caché des instructions Python

Une ligne de Python peut cacher une boucle. Voici les ordres de grandeur à connaître (ils sont à l'origine de la plupart des écarts observés au TP1).

| Opération | Coût | Remarque |
| --- | --- | --- |
| `t[i]`, `len(t)`, `t.append(x)` | O(1) (append en moyenne) | append : coût **amorti** constant |
| `t.insert(0, x)`, `t.pop(0)` | O(n) | tous les éléments sont décalés ; utiliser `collections.deque` |
| `x in t` (liste) | O(n) | parcours séquentiel |
| `x in s` (set ou dict) | O(1) en moyenne | table de hachage |
| `t[a:b]` (tranche) | O(b − a) | copie des éléments |
| `s1 + s2` (chaînes) | O(len(s1) + len(s2)) | concaténer en boucle donne un coût quadratique ; préférer `"".join(...)` |
| `sorted(t)`, `t.sort()` | O(n log n) | Timsort, O(n) sur une liste déjà triée |
| `heapq.heappush`, `heappop` | O(log n) | tas binaire |
| `bisect.bisect_left(t, x)` | O(log n) | mais `bisect.insort` est O(n) (décalage) |
| construction d'un `set`/`dict` de n éléments | O(n) en moyenne |  |

**Complexité amortie.** `append` coûte parfois O(n) (quand le tableau interne est réalloué), mais la réallocation double la capacité : sur n appels, le coût total est O(n), soit **O(1) par appel en moyenne sur la séquence**. Ce n'est ni un cas moyen probabiliste, ni un pire cas isolé : c'est une garantie sur une séquence d'opérations.


##  Aide-mémoire

- **Θ** donne l'ordre exact, **O** une borne supérieure, **Ω** une borne inférieure ; on précise le cas (meilleur, pire, moyen).
- Séquence : on garde le plus coûteux. Imbrication : on multiplie. Boucle dont le travail varie : on écrit une somme.
- Somme 1 + 2 + … + n = n(n+1)/2 = Θ(n²). Série géométrique 1 + 1/2 + 1/4 + … ≤ 2.
- Réduction de la taille par division (÷ 2) : log₂ n tours. Réduction par soustraction (− 1) : n tours.
- En Python : méfiez-vous des boucles cachées (`in` sur une liste, `insert(0, …)`, tranches, concaténations de chaînes).
- Une **mesure** (pente log-log) peut confirmer une analyse ; elle ne la remplace pas.
